# Going: timed events Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Events the user marks as going become timed calendar events with their own hours.

**Architecture:** A private `data/going.toml` is loaded into `Catalogue.going`; `predict_one` attaches the hours to the `Prediction`, which then reports itself as timed. Sync needs no change: the payload, and so the fingerprint, changes.

**Tech Stack:** Python ≥ 3.15, Click, pytest, uv.

**Spec:** `docs/superpowers/specs/2026-11-16-going-design.md`

## Global Constraints

- Going marks live only in gitignored `data/going.toml` (`config.going_file()`); no tracked file names one.
- Default hours 18:00 to 22:30.
- British English; designed terminal output; `--json` stays plain.

## Review Focus

- End at or before start (18:00 to 00:30): the event ends the next day, never before it starts.
- A mark for a society that is unknown, visiting or not active: a load problem / refused by the command.
- Marking the same event twice: the newer hours replace the old, one entry kept.
- `going.toml` missing: everything works as before.
- A mark whose year has no prediction (out of order, or this year after Lewes night with no known date): nothing breaks; the listing says so.
